# Changelog

## [0.1.18] - Unreleased

Upstream sync + smoke-test restoration on the v4.0.0 SDK architecture (dev builds use VSIX labels only; notes accumulate here until Stable).

### Added
- 🧪 **Parallel commands and mid-run detach are proven by tests** — two tool calls built from one model response once shared a single terminal, so tests that only cover sequential handouts prove nothing about the bug that actually bit. The contract is now pinned at both layers: the VS Code-host mocha suite proves genuinely parallel terminal lookups get distinct terminals — same working directory and through the reuse path's awaited `cd`, the interleaving window where a second call could grab the terminal being handed out — and that a terminal whose command was detached with "Proceed While Running" stays reserved until its command actually completes, so the next command cannot write into a shell still running the previous one. The unit suite proves two parallel commands through one manager land on different terminals and their outputs cannot mix even when lines arrive interleaved, and that detaching one of two parallel commands leaves the other's result completely clean while the detached command's later output reaches only its own log file.
- 🏢 **Organization provider policy in the e2e harness** — the mock control plane can publish a remote config (`/.test/setRemoteConfig`) and now serves the endpoints the extension actually reads (`/users/me/remote-config` discovery + `/organizations/{id}/remote-config`), so the blocked-provider path is proven on a real VS Code window instead of only in unit tests: a "Cline only" policy is applied by moving the account into the organization through the Account view, and the test asserts the lock on every provider the policy excludes, the in-place notice after clicking one of their models, and that the active model did not change.
- 🔄 **Upstream sync (v4.0.0 SDK migration)** — merged 124-file conflict resolution + 16 post-sync commits from `upstream/main` (@ `402b9994d`). iCline now runs on the new SDK architecture (`@cline/shared`, `@cline/llms`, `@cline/agents`, `@cline/core`). Sakana/Jan/zenmux providers registered as SDK `BuiltinSpecs` with the `openai-compatible` family.
- 🛡️ **Guardrails re-injection** — `getIclineHarnessOverlay` re-injected via the SDK `buildClineSystemPrompt()` `rules` slot; `verifyWrittenFile` re-injected via the SDK `afterTool` hook (verifies `editor` + `apply_patch` targets; failure replaces the tool result so the model cannot claim a write that did not land). Covered by 10 tests.
- 📡 **zenmux dynamic model list** — `modelsSourceUrl` added to the zenmux builtin spec so the SDK's generic `resolveProviderModels` RPC fetches the live model list (supersedes the orphaned `refreshZenmuxModels.ts` handler).
- 🆕 **Upstream features ported to main** — Claude Sonnet 5, GPT-5.6 ChatGPT, ClinePass full enable, DeepSeek reasoning `xhigh`, Vertex models, Kimi K3 ClinePass fallback, task lifecycle telemetry, Claude Code/Codex optional peer deps, SDK OAuth retry + teammate run fixes.
- 📋 **Upstream sync plan** — `docs/icline/upstream-sync-plan.md` documents the v3.89.2 → upstream/main merge strategy with 7 phases.
- 🐟 **Sakana.ai provider** — Fugu / Fugu Ultra via OpenAI-compatible API (`https://api.sakana.ai/v1`); Pay-as-you-go and Subscription plan modes; Responses API (default) and Chat Completions; models `fugu`, `fugu-ultra`, `fugu-ultra-20260615`
- 🔔 **Welcome update bar (Phase 2)** — dismissible in-webview notices on the welcome home for new iCline releases and optional upstream Cline ahead signals (reuses `iCline.updates.*` settings and dismiss state)
- 📚 **Provider docs** — `docs/provider-config/sakana.mdx` and `docs/provider-config/jan.mdx` added to the docs site navigation

### Fixed
- 🧪 **The mocha suite's failing plus-button test is cleared** — the suite had reported 207 passing / 1 failing for rounds on a product that was fine: `extension.test.ts` executed `cline.plusButtonClicked`, an upstream command id this fork has not registered since the migration renamed the prefix to `iCline.*` (package.json and the registry agree on `iCline.plusButtonClicked`), so the command simply did not exist. The test now derives the command id from package.json instead of hardcoding a prefix — it will follow the next rename instead of failing again — and asserts the command is registered before executing it. One permanently failing test in a suite is where the next real regression hides, so the noise had to go.
- 🧮 **A filler in `insert_line` no longer fails the whole editor call** — the field is optional, and the way a model leaves an unused optional field is to write something empty into it: zod's `coerce` turns `""`, `"   "` and `false` into `0`, which the executor then refused with `Invalid insert_line: 0`. The dev.6-fix.30 log refused it eleven times while the model re-sent the identical call, and re-sending rather than correcting is what a filler looks like — a model that meant to insert at the top writes `1` once the error says "positive one-based". Since `0` can never be a one-based boundary, it now means "not provided", so the replacement the call describes runs; a value that really is an unusable boundary (a negative number) still reports itself with nothing written, and the preview reads the field the same way instead of skipping its tab.
- 🖥️ **Two commands can no longer be written into one terminal at the same time** — a tool call was handed a terminal before anything marked it busy, so every call built from the same model response ran the lookup to completion first and all of them got the same terminal; `runCommand` then did not check the flag either (it logged it and wrote anyway) and its `processes.set()` dropped the previous process for that terminal. The 1-Cline log shows the outcome: three commands written into terminal 19 within one millisecond, output attributed to the wrong call, and a completion promise that never settled — a command that reads as hung until the user intervenes, which is one of the ways "the agent stalled on a command" presented. A terminal is now reserved at handout and released only when the command it was fetched for completes.
- 🔓 **A rotated OAuth token no longer costs every compaction its summary** — the summarizer builds its own LLM handler from `config.providerConfig`, but `syncOAuthCredentials` only refreshed `session.config.apiKey` and the agent connection, so `/compact`-class summarizer calls kept sending the token captured when the session started. The dev.6-fix.30 log shows it exactly: `Agentic compaction summarizer diagnostics {summarizerProviderId:"cline"}` → `[ai-sdk] stream error` → `Agentic compaction failed; falling back to basic compaction {"errorMessage":"Unauthorized: Please make sure you're using the latest version of Cline and re-authenticate…"}`, with the access-token hash rotating underneath it. The refreshed key is now written into the same provider config the summarizer reads, and a summarizer that still meets an auth error refreshes once and retries (re-resolving the provider config, which is a copy) before basic compaction is considered — the same recovery chat turns already get.
- 🔁 **Agentic compaction falls back only when the summarizer really produced no summary** — the fallback keyed off the strategy returning nothing, which is also how every deliberate skip reports itself (transcript too short, no safe cut boundary, nothing new above the cut, summarizer budget exhausted, summary input budget failed). It therefore overrode the `nothing new above the cut to fold` guard and re-folded the transcript on every turn while the estimate stayed over the trigger — the per-turn compaction storm that guard exists to prevent. The strategy now reports *why* it declined, and a deterministic basic fold is reserved for `no_summary_text` (the reasoning-model case the fallback was added for).
- 📊 **The context bar shows the measured post-compaction size, immediately and after reopening** — the bar reflects the last `api_req_started` row, which still described the pre-compaction request, so it stayed stuck at 100%+/400k. Compaction now records the measured request tokens before and after (`context_usage` on the persisted sidecar), the VS Code bar prefers those numbers and falls back to scaling the last real usage by the message-count ratio when a build supplies none, and reopening a chat reads the measured value instead of estimating from message counts. The field is declared once (the prepare-turn result), so the app no longer carries a hand-rolled copy of a shape the runtime writes.
- ✅ **YOLO mode and the auto-approve switches now reach the SDK's tool policies** — `buildToolPolicies` ignored the settings it was handed and forced `autoApprove: false` for every governed tool, relying on a live guard that only understood the per-action toggles; nothing in the VS Code SDK adapter read `yoloModeToggled`, and core's own yolo policy preset was never called. YOLO therefore approved nothing, and a tool that still asked left no trace at all. YOLO is now threaded into both the policy map and the live guard (re-read each call, so toggling it mid-task counts), a refused auto-approval update re-posts the authoritative state instead of vanishing — the webview derives its next version from what it last received, so a silent drop left a client unable to change anything until a reload — and the ask path logs `Tool approval required (not auto-approved): tool=… policyAutoApprove=…` so a stall is diagnosable instead of guessed at.
- 📄 **An editor call writes a file of any realistic size, atomically (dev.6-fix.30)** — the tool refused `new_text` past 32,000 characters, so the fix.29 smoke hit `Editor input too large: new_text was 40243 characters` on an ordinary file and paid a second provider round trip to land it. The ceiling is now a 2,000,000-character safety net that only catches payloads one response could not have produced; 32,000 survives as the chunk size the recovery recipe names (`EDITOR_CHUNK_CHAR_LIMIT`), never as a number the model is taught to shrink for — the harness overlay now states the behavior with no numeric cap at all. Every write — `editor` and `apply_patch` alike, through one shared temp-file + rename path — lands all-or-nothing, so a failed write leaves the target exactly as it was (file mode and symlink target included), a patch that dies midway changes nothing, and no `.icline-tmp` litter remains. The refusal that remains is shown once: the guardrail no longer appends a second paragraph of the same notice, which is what the fix.29 chat displayed.
- 🪟 **The Options panel expands fully again instead of scrolling (dev.6-fix.29)** — dev.6-fix.28 answered the jump below by anchoring the panel's top to its row *and* bounding its height by the room left under that row, and a low row then met a scrollbar where it used to meet a whole panel. The panel is lifted instead: its own height decides how far, so its bottom rests on the picker's bottom margin, and its `max-height` is back to the mock's flat 320px. Content that changes after the panel is placed (the clamp notice appearing on a toggle) can still grow or shrink it, but only from the top the user is already reading.
- 🧷 **Toggling Thinking no longer slides the Options panel off its row (dev.6-fix.28)** — two separate causes, both real. The host's answer was cached under a key that included the level in force, so the moment the switch wrote `none` the panel had no answer for its new question and drew the provider's generic six levels (plus a notice about `Minimal`) until the real answer landed — the level list flickered and the mark moved on its own. And the panel's top was clamped against its own rendered height, which the switch changes, so every click slid it up or down under the cursor. The answer is now cached per model and per level separately (the model's levels survive a switch), and the placement is re-measured once per hovered row: a content change can no longer move it.
- ⏱️ **A provider stream that goes silent is retried instead of hanging (dev.6-fix.28)** — a stream that stopped producing output with the request still open raised nothing, so nothing retried it: the AI SDK retries only the start of a request, the empty-response middleware only sees a turn that ended, and turn-level retry needs `finish` to report an error. Streams that produce no output at all for 120 seconds (reasoning and tool-call parts count as output) are now aborted as a retryable provider error, so the existing backoff handles them — no dialogue, no manual Retry. Cancelling yourself still cancels, because that abort is classified terminal.
- 🧩 **A tool call a model wrote in an element form is now understood (dev.6-fix.27)** — the recovery added in dev.6-fix.25/26 still missed what GLM 5.3 Flash actually wrote at the end of a real chat: a tool name as a tag with its arguments as child elements and no call syntax anywhere. The scanner now matches the real tool set (so HTML a model is *writing* is never mistaken for a call) and recovers those calls, which means the command runs, the output comes back, and no markup is left in the balloon.
- 🎚️ **The Options panel lists the Effort levels the model really takes (dev.6-fix.27)** — the provider's list is a vocabulary, not a fact about the model: `z-ai/glm-5.3-flash` takes Low/High/Max, so offering it the generic six (with `Minimal`) was a lie the SDK silently clamped on the way out. The panel is now narrowed by the host's own answer — the same function the request path uses — and re-enabling Thinking lands on the model's first real level instead of the vocabulary's, so the switch no longer writes a level the SDK has to correct.
- 🗒️ **A tool call written as text with no closing tag is recovered (dev.6-fix.26)** — the parser expected a closing tag, so `<tool_call>run_commands{"commands": […]}` scanned as nothing at all and the markup stayed in the chat. Arguments are now read with a brace matcher, and a `name{…}` shape is only treated as a call when that JSON parses as an object, so prose that merely shows markup is left alone.
- 🧭 **The Cline free route has its own catalog entry again (dev.6-fix.26)** — the picker folded `z-ai/glm-5.3-flash` into the paid OpenRouter spelling `zai/glm-5.3-flash`, but they are two different routes, and the free one is the id the app actually offers. Dropped, the row had no metadata at all: no capability icons, an Effort list from the generic vocabulary, and a Thinking switch that existed only while a level was already set — turning it off made the model permanently unconfigurable. Both ids are kept now, and `none` counts as a level the user chose, so Thinking turns back on.
- 🧯 **A tool call the model wrote as plain text is recovered and run (dev.6-fix.25)** — some models answer with the call in their message instead of a `tool_use`: the turn looked finished, no tool ran, and the chat showed the call as text. The runtime now recovers the call, strips the markup from the message, runs the tool once, and says so in the transcript — with a log line and a telemetry event, because a silent recovery is how two smoke rounds were lost. A call that names a tool the run does not have fails with the list it does have, and a turn cut off by `max-tokens` is never guessed at, since half an argument is not an argument.
- 🏃 **Leaving a chat no longer kills the run (dev.6-fix.24)** — navigating to the home screen or another chat stopped the task that was working, because the in-memory session went with the view. A running session is parked instead: its task, transcript and pending questions are kept, its events keep landing in that transcript, and the turn carries on in the background. A second request queues behind it, the background task is announced when you come back (including an answer you still owe it), and the Recent card carries a `Working` / `Waiting` badge so you can see which chat is busy without opening it.
- 📄 **One editor call can now write a whole file (dev.6-fix.23)** — the `editor` tool rejected `new_text` past 6,000 characters, so any HTML/CSS/JS file longer than that was refused before it touched disk and the model split it into 2–4 extra requests, each a full provider round trip. The per-call limit is 32,000 characters, and the old 6,000 survives only as guidance in the tool description, where it no longer refuses anything. The refusal that remains names the real size, says nothing was written, and gives the way to send it in chunks — once, not twice.
- 🖼️ **Images are downscaled before they reach the model (dev.6-fix.23)** — a picture stays in the transcript and is re-sent on every later request, while providers already shrink what they accept, so pixels past 1,568px were paid for on every turn and seen by nobody. PNGs are downscaled where they enter (`read_files`, and images you attach), with a dependency-free codec that leaves anything it cannot handle byte-for-byte (GIF, JPEG, WEBP, interlaced or 16-bit PNGs, or a re-encode that would not be smaller), and the oversize fallback in the message builder now shrinks to fit instead of dropping the image.
- 📏 **Images no longer make the context estimate explode (dev.6-fix.22)** — the estimator charged a request for the base64 length of every image, counting one ~1MB screenshot as ~300,000 tokens instead of the ~1,600 the provider bills, so two pictures read from disk pushed the estimate over the auto-compact threshold on a 1M-window model that was 17% full — and every `auto-compacting` / `auto-compaction-skipped` pair that followed was that same miscount, with the next request carrying the images again. Image payloads are folded to a flat per-image estimate on every path (request estimate, compaction trigger, keep-recent budget, cut point), compaction diagnostics now reach the log in a packaged build, and every silent skip says why.
- 🕒 **The Recent cards say when a chat was last used (dev.6-fix.22)** — `just now` → `14:32` → `Yesterday` → `Fri` → `Sep 10`, with the full date on hover, so the order of a history list is readable at a glance. Card height and the grid are untouched.
- 🧮 **Recent shows up to nine chats in three columns (dev.6-fix.21)** — the home screen kept one column of three, leaving the rest of the row empty next to short session names, so `View All` was the only way to reach a fourth chat. The grid now fits 240px cards side by side (three at the ~843px working width, two around 600px, one in a squeezed sidebar), three rows as before, so nine chats are one glance away.
- 💾 **A draft in the chat box survives moving the view (dev.6-fix.21)** — moving the iCline view to the Secondary Side Bar (or back) makes VS Code create the webview again, and the text and attachments that had not been sent yet went with the old one. The draft is kept per slot, with text and attachments stored separately so typing never re-serializes an image, and it is read before the first paint and cleared by sending — no save step anywhere.
- 🪟 **Moving the iCline view no longer empties or resets the chat (dev.6-fix.20)** — disposing a view was treated as the end of the session, so dragging the view to the Secondary Side Bar (or to the other side of the panel) attached the new view to a controller that had already been torn down, and the chat came up blank. A second cause of the same confusion cleared the task on every view resolve, which threw away a conversation that was only being moved. Nothing but an extension deactivate ends a session now, and a view that appears later receives the current state on mount — so a moved view keeps its history and can carry on.
- 🧭 **Popover behaviour is one shared module, so menus cannot drift apart (dev.6-fix.19)** — the anchoring rule (left edge of the panel on the left edge of the button that opened it, the older right-edge behaviour once the pane cannot hold it), the hand cursor over a whole menu and the text cursor inside a field now live in one place that every iCline menu uses, with a source guard that fails when a new menu skips them — and a real-window test that widens the pane and watches an open Options panel move onto the button's left edge.
- 🖱️ **Drop-down and menu surfaces use the hand cursor, and attachments sit above the chat box (dev.6-fix.18)** — the Quick Picker and the Options panel no longer show the OS arrow (the same hand the composer buttons already had), an open Options panel takes the button's left edge when the pane is wide enough and keeps the older behaviour when it is not, and thumbnails you paste or attach moved to the top of the chat box and got bigger (44px over the transcript's 34px), with the textarea and the mention/slash highlight layer reserving the same first-line space.
- 🎛️ **The status icons are their own button, and they open Thinking/Effort for the model in use (dev.6-fix.17)** — the capability icons and effort badge under the chat input were part of the model-name button, so changing the Effort of the model already driving the chat meant opening the model list and finding its row. The chip is split: the name + chevron opens the model list, while the readout is a separate button that opens the very same Options surface a picker row shows — for the ACTIVE model — so a level or the Thinking switch can be changed without switching models (the writes go through the active model's running configuration, not a stored preference). The panel body is now one component (`components/chat/ModelOptionsPanel`) rendered by both the hover panel and this popover, so the two surfaces cannot drift apart.
- 🔒 **A provider your organization does not allow is answered, not silently reverted (dev.6-fix.16)** — the Settings provider dropdown already hides providers outside the organization's allowed list, but the Quick Picker lists every provider's models, so a click on a blocked one looked successful: the host's remote-config layer (org policy — highest precedence) kept the pinned provider, and the chip snapped back on the next state push with no explanation. Blocked providers now carry a lock in the picker, and clicking one of their models says why in place instead of committing a selection that cannot take effect.
- 🔇 **A downgraded Effort level is now announced (dev.6-fix.15)** — Effort is stored once per mode, not per model, and every dropdown deliberately offers the app's full vocabulary, so a level can be in force for a model that does not accept it. The SDK gateway narrows it on the way out (`max` on a model whose top level is `high` reaches the provider as High, a model with no effort control gets none) and nothing said so — you had to compare the provider's answer with the dropdown. Both places that SET an effort now name the level that really goes out: the Quick Picker's Options panel and the Settings Effort control render the same sentence from a host answer, and the answer is not a second opinion — the host calls `decideReasoningEffort`, the very function the gateway calls for every request, with the model's controls read from the registry the gateway resolves it from. Nothing is claimed while the answer is unknown, when the level is sent as chosen, or when a thinking budget is what actually goes out. A scan of the whole registry (every provider and model the gateway can resolve, every level) fails the build if a clamp ever stops fitting one of the two sentences the notice knows.
- 🧭 **Settings snapped back to Cline after choosing a model (dev.6-fix.15)** — selecting a model on the xAI page (or any provider form) committed the model but left the page showing the Cline provider again. The commit writes provider+model into the settings layers, and the remote-config layer — org policy, highest precedence — silently outranked it because `setApiConfiguration` also fed that cache, and provider fields survive its filter. Any earlier settings write therefore pinned whatever provider was current at the time, permanently: the model id updated (which is why it looked like a UI bounce) while the provider did not. Ordinary writes no longer touch the remote layer (only the control-plane fetch populates it), covered by a unit test on the precedence layers and an end-to-end test on a real VS Code window that picks a Grok model and asserts the page stays on xAI.
- 📐 **An open dropdown was covered by the control below it (dev.6-fix.15)** — Sakana's Model list opened *behind* the Reasoning Effort box, and ZenMux's API Protocol list behind Provider routing. Two positioned siblings with equal z-index are decided by DOM order, so the later control always won; the forms now descend instead — the first control takes the top of a shared ladder (`formDropdownZIndex`), and a test pins that ordering for the real styled container.
- 🏷️ **The model chip under the chat input showed no status (dev.6-fix.15)** — the Quick Picker's rows carried capability icons and the effort badge while the chip next to the composer showed a bare model name, so effort/reasoning state was invisible unless the picker was open. Both now render one component (`ModelStatusIcons`) from the same per-model status, with the same balloon tooltips.
- 🎚️ **Effort levels were silently downgraded before the request left the host (dev.6-fix.14)** — the app kept its own 5-value effort list (`none`/`low`/`medium`/`high`/`xhigh`) while the SDK accepts 7 (`minimal` and `max` as well), and every unrecognized value was rewritten to `medium`. Sakana's **Max** therefore reached the provider as *Medium*, and `minimal` from a catalog that publishes it could never be stored at all; on top of that the last gate before the request forwarded only `low`/`medium`/`high`, so `xhigh` was dropped too. The app now stores exactly the SDK's vocabulary (a parity test fails the build if the two lists drift), both gates forward the full set, and the SDK gateway — not the UI — clamps a level the selected model does not advertise. Settings offers the same set, so what the dropdown shows, what the app stores, and what the provider can receive are one vocabulary.
- 🐟 **Sakana Settings showed two forms at once (dev.6-fix.14)** — Sakana declares the `openai-responses` protocol in its SDK listing, so the settings registry classified it as a generic provider and rendered the shared OpenAI-compatible form *on top of* the Sakana form: two API-key fields and two model pickers in one pane. Sakana is now registered as a provider with its own form, and the duplicated pricing links in its intro paragraph are gone (the Pay-as-you-go / Subscription buttons below already own those actions).
- 🎛️ **Quick Picker hover panel missing, then stuck on the first rows (dev.6-fix.9 … fix.11)** — hovering a model never opened the Options panel: the handler was attached in an effect keyed on the popover's open state, and Radix mounts the popover body one commit later, so the effect ran while the list ref was still null and — its dependencies never changing again — never re-ran. Once it opened, placement clamped against the panel's 320px *max* height instead of its real height, pinning every row more than ~90px down to one top. Both are fixed against the locked design's own rule, measured from live rects. The panel now matches that design (Options title, model id, Thinking switch, Effort levels, capability list), and it and the row's status icons and effort chip read the same per-model status — before, the row was never handed the real values at all, so a model with an effort set showed no chip while the panel showed its level.
- 📏 **Effort / Thinking controls disagreed between Settings and the Quick Picker (dev.6-fix.12 … fix.13)** — "which models get an Effort control or a thinking budget" was decided in ~15 provider forms, each with its own copy of the rule (some id-based, some metadata-based, some with hardcoded model lists), and the picker had a fourth variant; "which values that control offers" was hardcoded in the UI too (the adaptive set spelled out six times, Sakana's three levels inside its own component). Both halves are now a single provider-metadata table (`webview-ui/src/utils/modelThinkingOptions.ts`) that Settings and the picker call, so the two surfaces cannot show different controls or different levels for the same model. Sakana's effort control is reachable again without a previously-stored value, and Fugu Ultra still defaults to X-High.
- ✍️ **Rejected file edits reported as success (dev.6-fix.7)** — the write guardrail judged only `isError`, while the SDK returns input-level rejections as a result envelope that does not throw; an oversized `editor` call therefore overwrote the evidence with ENOENT and an edit whose `old_text` did not match was not flagged at all. The envelope is now inspected before verification, the tool's own claim is recorded, and a rejected edit ends as a failed row carrying the real message. The harness overlay teaches the chunking rule, `ICLINE_TOOL_TRACE=1` writes a JSONL trace for diagnosis, and the oversized-write path is now covered end-to-end in a real VS Code window.
- 🧭 **Harness overlay demanded tool usage (dev.6-fix.5)** — the iCline harness overlay was rewritten against the official prompt after a controlled diff, so a conversational reply is no longer pushed into a tool call it has no reason to make.
- 🪞 **Provider selection echo + Jan / ClinePass follow-ups (dev.6-fix.4)** — the provider selection echo, the Jan picker falling back to the server's model list, and the ClinePass flag defaults were corrected, and the provider stats card no longer overlaps the form.
- 🖱️ **Provider/model selections not sticking (dev.6-fix.3)** — clicking a provider or model in Settings or the Quick Picker committed correctly on the host but the visible selection snapped back or froze. Three stacked causes, all fixed at the root: (1) applying a saved reasoning-effort preference AFTER the commit sent the pre-click api configuration snapshot wholesale, reverting the fresh selection — the trigger (saved reasoning settings in the shared providers.json, written by official Cline) became common only now; the effort preference is applied before the commit and configuration writes read live state instead of stale render closures. (2) A single failed state-push delivery permanently silenced state updates for the session (pushes now retry before a subscriber is dropped, and the webview re-subscribes after a stream error). (3) The first edit to a debounced field (e.g. Base URL) after opening settings was silently swallowed.
- 🗂️ **Provider settings parity with official Cline (dev.6-fix.2)** — Sakana's model list now flows from the auto-updated generated catalog (8 models incl. Fugu Ultra v2 and Namazu, with prompt-cache capability) instead of a stale hand-written list, and Jan uses the same rich OpenAI-compatible settings form as official Cline: the model list refreshes automatically from the Base URL you configure (Jan's port is configurable), custom model IDs and headers included. Jan itself remains iCline-only — it is not on models.dev. A rounded summary card above the API Provider dropdown shows the live catalog totals: Providers, Models, and Free (Cline free-tier) counts.

The user's Max Output Tokens setting is now mirrored onto the summarizer's provider config, and the summarizer logs a diagnostic when it gets no summary text instead of failing quietly.

- 🧭 **Harness overlay referenced a tool that does not exist (fix.35)** — the iCline harness guardrails overlay, injected into every session's system prompt, instructed the model that conversational ACT MODE replies must use `attempt_completion` or `ask_followup_question` — a classic Cline tool name that is not in the SDK runtime (the real tool is `ask_question`). Obedient models would hit a fail-fast rejection, and small models derailed into restart loops while the same model on the same prompt ran cleanly on official Cline (verified via a controlled comparison and session transcripts). The overlay now references only real runtime tools, backed by a vitest regression guard (suite migrated from the Electron-only mocha host) asserting the overlay never mentions stale tool names.
- 🔁 **Repeated "Task Completed" after every reply (fix.34)** — iCline's own `attempt_completion` tool (created during the v4.0.0 SDK migration; upstream has no such tool) never set `lifecycle: { completesRun: true }`, so the agent runtime never treated a completion as terminal. The completion text echoed back as a tool result and the model answered with another `attempt_completion` — 1–3 repeated "Task Completed" rows after any user reply, plus 1–3 wasted full-context requests per completion, until a plain-text reply happened to end the turn. The tool now carries the same flag as the SDK's built-in `submit_and_exit`, so completing a task ends the turn and waits for feedback, exactly once.
- 📏 **Runtime sessions ignored the real cline-free context window (fix.33)** — the fix.32 llms rebuild fixed the *display* pipeline, but SDK sessions still read knownModels from the bare `@cline/llms` registry, which has no `cline` rows at all (live-catalog models never register into it). The committed-runtime-model injection is preserved (user overrides still win). Note: sessions opened before updating keep their old budget — start a new task to pick it up.

The \`@cline/llms\` runtime bundle was rebuilt to include the fix.26 live-catalog merge (recommended/free models now resolve real OpenRouter specs — context window, capabilities, $0 pricing — into the \`cline\` collection), so the compaction trigger, manual-compact target budget, and the context bar all read the same source of truth.
